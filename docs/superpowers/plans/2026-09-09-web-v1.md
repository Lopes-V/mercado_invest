# Mercado Invest Web v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the private Vercel-hosted administrative dashboard specified in `web/TASKS.md`, while preserving the Python investment pipeline as the only decision engine.

**Architecture:** A Next.js App Router project in `web/` keeps privileged Supabase and GitHub clients server-only. Signed administrative cookies guard every dashboard page and mutation; Server Components obtain read models and Client Components render interaction, charts, filters, and mutations. The existing Python scheduler reads a single allowlisted runtime setting from Supabase and continues to own Telegram delivery.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS, React, Recharts, `@supabase/supabase-js`, Argon2id, JOSE, Node test runner, Python/pytest, Supabase migrations.

**Spec:** `web/2026-09-09-web-dashboard-design.md`; `web/TASKS.md`.

## Global Constraints

- The frontend only renders persisted facts; it never calculates financial scores, changes `candidate-v1`, or replaces Python automation.
- All privileged credentials are server-only, never `NEXT_PUBLIC_*`, and never logged.
- Every financial datum renders its persisted timestamp when available; missing, invalid, and stale data are explicit states, never zero substitutions.
- All mutations require the administrative session and same-origin verification.
- Preserve the disabled production gates, GitHub workflow semantics, Telegram independence, backend policy, and database history.
- Use test-first for new observable validation, mapping, authentication, and scheduler behavior. Bootstrap configuration is an explicit exception: it has no application behavior to test before Next.js creates the executable project.
